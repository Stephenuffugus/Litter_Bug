## 1. Art banks

Six layers drive bug anatomy. Targets come from HANDOFF §3.2. We have
placeholder versions of each; real art replaces the placeholders by
overwriting the same filenames (PNG layers) or by editing the JSON
(procedural layers).

| Layer | Kind | Current | Target | Need | Spec |
|---|---|---|---|---|---|
| wings | PNG 256×128 | 8 | 40 | 32 | `assets/wings/README.md` |
| bodies | PNG 200×100 | 8 | 30 | 22 | `assets/bodies/README.md` |
| heads | PNG 96×96 | 8 | 25 | 17 | `assets/heads/README.md` |
| patterns | PNG 200×100 | 8 | 50 | 42 | `assets/patterns/README.md` |
| legs | JSON params | 8 | 20 | 12 | `assets/legs/README.md` |
| antennae | JSON params | 8 | 15 | 7 | `assets/antennae/README.md` |

Workflow per layer: see the layer's README. All four PNG layers use
the same drop-folder pipeline (`raw/` → `npm run <layer>`). The two
procedural layers are edited as JSON directly.

Run `npm run art:contact` to regenerate all four PNG contact sheets at
once. Each one lives at `assets/<layer>/contact-sheet.png`.

## 2. Palette

The lab currently has 16 fixed hex colors in `bug-lab.html` (the `PAL`
array). HANDOFF §3.2 names 80 palettes as the launch target, but a
palette in the game sense is probably a *group* of hex colors that go
together, not a single color. Open question: do we want 80 distinct
4-tuples of {primary, secondary, accent, dark}, or 80 distinct
single-color anchors?

**Decision pending:** palette structure + count.

Once decided:
- Replace the 16-color flat array with a structured palette catalog
- Hash bytes 18-21 currently index four nibbles into the flat array.
  Rework to index a palette entry instead.
- New file: `assets/palettes/palettes.json` + import-art entry?

## 3. Trait byte mapping (current)

Where each byte of the SHA-256 hash goes:

| Byte | Purpose | Range | Lab var |
|---|---|---|---|
| 0 | body index | % BODY_BANK | `t.body` |
| 1 | body scale variation | 0.92..1.08 | `bodyScale` (inline) |
| 2 | unused (was bodyW in old code) | — | — |
| 3 | unused | — | — |
| 4 | head index | % HEAD_BANK | `t.head` |
| 5 | head size variation | 40..52 | `headW` (inline) |
| 6 | unused | — | — |
| 7 | unused | — | — |
| 8 | wing index | % WING_BANK | `t.wing` |
| 9 | wing scale variation | 0.85..1.14 | `t.wingScale` |
| 10-11 | unused | — | — |
| 12 | leg-set index | % LEG_BANK | `t.leg` |
| 13 | unused | — | — |
| 14 | antenna-set index | % ANTENNA_BANK | `t.antenna` |
| 15 | unused | — | — |
| 16 | pattern index | % PATTERN_BANK | `t.pattern` |
| 17 | unused | — | — |
| 18 | palette nibble 0 (primary) | 0..15 | `t.palette[0]` |
| 19 | palette nibble 1 (secondary) | 0..15 | `t.palette[1]` |
| 20 | palette nibble 2 (accent) | 0..15 | `t.palette[2]` |
| 21 | palette nibble 3 (dark) | 0..15 | `t.palette[3]` |
| 22 | behavior tag | % 12 | `t.behavior` |
| 23-31 | reserved (climate in Lucid Winds, unused here) | — | — |

That's only 13 bytes meaningfully consumed out of 32 available. Lots
of headroom for new layers without restructuring.

## 4. Game systems still to build

What the lab does NOT do yet, that the game needs.

### 4.1 Bug creation flow

- **Trash inventory.** The player's bag of foraged items.
- **Incubator UI.** Combine 2+ trash items, see preview, commit.
- **Hatching ceremony.** Mini-game (sift / pin / hatch — HANDOFF §4.4)
  that takes touch input, hashes it, finalizes the bug seed.
- **Procedural bug name generator.** Current 2-word generator
  (`bugName(hash)` in `bug-lab.html`) is a stub. Real version reads
  bank metadata + behavior tag → contextual name.

### 4.2 Trash catalog

Already prototyped in `LitterBug.jsx` (referenced in HANDOFF §11) but
not in this repo yet. Tables to port:

- `TRASH_ITEMS` — { id, name, icon, tags[] }
- `SIGNATURE_RECIPES` — explicit pair → hero bug
- `SIGNATURE_BUGS` — named hero species with lore

Scaling targets (HANDOFF §6.3):

| Phase | Items | Recipes | Hero bugs |
|---|---|---|---|
| Prototype | 20 | 12 | done |
| Alpha | 100 | 40 | hand-authored |
| Beta | 300 | 100 | community pipeline |
| Launch | 1000+ | 150 | procedural from OSM |

### 4.3 World layer

- Leaflet.js map + CartoDB or OSM tiles
- POI spawning from OSM categories (cafes → coffee cups, etc.)
- GPS geo-walk: collect within ~30m of a pile
- Bug release UI (player picks a territory)
- Territory polygons rendered on the map
- Breeding sim (port from Lucid Winds `_doCrossPollination` / `FG_Wild`)

### 4.4 Scanner

- Barcode reading via `@zxing/library` (already in `package.json`
  dependency wishlist — not yet wired)
- Server-side per-barcode dedup (once per 24h global)
- Themed reward tables tied to barcode hash

### 4.5 Bugdex (collection)

- Grid view of owned bugs
- Detail card: large bug render, name, lore, stats, hash
- Filtering by rarity / palette / anatomy
- Share / download bug card (canvas export)

### 4.6 Save & sync

There is currently NO save layer. Three paths:

1. localStorage only (v0, works offline, no cross-device)
2. Inherit Lucid Winds Firebase wiring (auth + Firestore)
3. Fresh Supabase project (HANDOFF §7 recommendation)

**Decision pending:** save backend.

### 4.7 Onboarding

- Cinematic intro (4 beats, similar to Lucid Winds PW_Onboard)
- First-bug ceremony (gift bug to anchor the collection)
- Tutorial tap-loop
- Permission asks (camera, location) with clear copy

### 4.8 Mini-games

The Lucid Winds engine has 27 mini-games. HANDOFF §4.4 suggests we
build ONE first (Sift, Pin, or Hatch). Pick one and ship.
